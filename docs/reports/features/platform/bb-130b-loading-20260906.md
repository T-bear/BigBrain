## Evidence

### Method and limits

`scripts/measure-browser-loading.mjs` attaches through Firefox WebDriver BiDi to a
dedicated empty profile, instruments fetch before React, blocks every non-GET fetch
and exports only an allowlisted endpoint vocabulary. Unknown path segments become
`:redacted`; all queries are dropped. Response bodies and headers are not exported.
Payload bytes are Resource Timing `decodedBodySize`, not object contents. HTTP status,
start, response end, duration, transfer bytes and cache availability are recorded.
`inFlightAtStart` counts fetches through response headers; body-transfer concurrency
can instead be reconstructed from start/end in the linked evidence. This is browser
concurrency, not the number of simultaneous server executions.

Firefox 140.12.0esr, isolated desktop/headless profile. Local storage is cleared for
each ordinary view. The separate `finance-cached` visit retains the cache generated
by the preceding successful Finance visit. HTTP cache and backend caches are not reset;
this is a cold application/view load, not a cold machine or database benchmark.
The script waits at least 6.5 seconds and extends incomplete initial reads to about
45 seconds. Details are then opened in cached Finance and Media for another 6.5 seconds.
It records Finance hero insertion as a structural meaningful-content marker, not a
paint metric. Home/Media data arrival is represented by request timings; no universal
first-content paint claim is made.

Baseline was the existing deployment: its `index-Betz0J5O.js` and `index-COc9e5Ag.css`
matched the freshly built baseline. After measurement used a local Vite production
preview (`index-CPjxMZ_M.js`, identical CSS), proxying GETs to the same existing API.
The extra preview hop, host load, cache warming and sequential sampling prevent a
causal latency/speedup claim. Production containers and Finance data were not modified.
Some samples overlapped local verification load. Request counts/trigger ordering are
the regression contract; individual latency samples are diagnostic evidence only.
Firefox console output retrieved at shutdown also contained script-timeout warnings;
their event time/cause was not attributed. This is an additional browser-verification
limitation, not proof of a new regression or a clean UX run. Preview and the dedicated
browser were stopped after measurement.

Reproduce from the repository using a disposable profile and locally supplied URLs:

```sh
mkdir -p TestResults/bb130/firefox
firefox --headless --no-remote --profile "$PWD/TestResults/bb130/firefox" --remote-debugging-port 9224 about:blank
node --experimental-websocket scripts/measure-browser-loading.mjs "$BB130_APP_URL" TestResults/bb130/before.json
# Build the candidate and serve its production bundle through a local preview
# with /api proxied to the same API; do not deploy for measurement.
node --experimental-websocket scripts/measure-browser-loading.mjs "$BB130_PREVIEW_URL" TestResults/bb130/after.json
```

Never attach the probe to a personal browser. Do not commit the browser profile.
The publication-safe event graphs are [before](bb-130b-before-20260906.json),
[after](bb-130b-after-20260906.json) and the [initial diagnostic sample](bb-130b-initial-20260906.json).
All measured samples recorded zero blocked writes: no application write was attempted.
`network` means positive browser transfer bytes; `cache-or-unavailable` is deliberately
not a claim of a confirmed cache hit. Finance local display cache is a separate contract.

In the warm comparison, Finance hero appeared at 738 ms before and 675 ms after;
cached hero appeared at 135 ms before and 254 ms after. These are observations, **not
statistically established improvements**. Both cached heroes preceded their observation
response. Initial diagnostic Home overview and Finance observation/overview did not
complete within approximately 45 seconds; later baseline and candidate reads did.
The cause of that intermittent latency remains unresolved. No timeout, entitlement
workaround, server rewrite or reinterpretation of scientific outcomes was introduced.

The warm baseline risk-evaluations payload was 275,979 decoded bytes, observation
178,531 bytes and downloads 186,196 bytes. These are useful payload hotspots, not
permission to trim evidence or redesign endpoints without a separate analysis.

Opening Finance details still starts nine existing reads (features, backtest catalog,
robustness catalog, datasets, backups, shadow, scheduler, governor, operations), with
selected-result reads following catalog completion. They never start on cold load.
The after detail sample reaches nine concurrent reads. This explicit on-demand burst
is retained and is **not** covered by the cold-load bounds above. Some detail requests
outlive the sample. No whole-platform concurrency cap is claimed.
Media technical overview and service links now start only when Administration opens;
before they loaded while closed. Media's existing jobs polling remains view-local.

## Changes

- `App.tsx`: a view-aware request owner under the existing WidgetProvider reads its
  active view, including saved/deep-linked views. State remains in App. Modules load
  in Family, recovery in Home/Admin, Docker/system in Admin. System polling pauses
  when hidden, resumes on visibility and cannot overlap; exit aborts its lifetime.
- `dashboard/HomeOverview.tsx`: a local three-slot hydration queue prioritizes the
  three core reads before two secondary reads. Any completed/failed read frees a slot;
  one slow read does not block every secondary card. Navigation aborts and discards
  queued work. `api.ts` and `shoppingListApi.ts` accept optional read AbortSignals.
- `finance/FinanceObservation.tsx`: the existing overview/risk/autonomous effects
  wait for an available observation, including the existing compatible cache. A
  refresh does not restart these effects. No cache version, copy, chart or gate changes.
- `MediaDashboard.tsx`: technical data follows accordion relevance; service links
  mount on open, overview polling stops on close and allows only one active read.
  Aborted/stale responses cannot replace newer state.
- Focused tests cover cold request sets, deferral, navigation cancellation, unresolved
  reads, hidden polling, Finance refresh isolation and closed Media administration.
- The standalone measurement script runs only when explicitly invoked, not in the app.
