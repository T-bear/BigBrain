## Security and concrete blocker

The current accepted `LibrarrAudiobookAcquisitionProvider` uses opaque discovery candidates and
hash-backed torrent jobs; it exposes no arbitrary direct-audio import operation. Reusing its
no-overwrite placement is the preferred boundary, but inventing a hash/candidate would violate
provider authority. `infrastructure/librarr/README.md` records the atomic exclusive placement
contract; this checkpoint does not alter that provider or its service.

The official [Audiobookshelf upload reference](https://api.audiobookshelf.org/#upload-files)
is marked unmaintained and describes existing-directory rejection. The observed upstream
[MiscController.handleUpload](https://github.com/advplyr/audiobookshelf/blob/743d9152208507a1dbf7c95c94290071338f44bd/server/controllers/MiscController.js#L33)
uses `ensureDir`, then file movement without an explicit exclusive-destination contract, and
responds 200 after per-file errors are caught. Source inspected on 2026-10-17; upstream master
resolved to the linked SHA. This is public source evidence, **not** verification of the deployed
server version, permissions or behavior. It is insufficient to establish safe no-overwrite
placement or successful indexing. A random filename reduces accidental collision probability
but is not a substitute for an atomic no-overwrite contract or exact catalog evidence.

Therefore **all fetching/import remains unreachable**: no HttpClient, DNS lookup, redirect,
subprocess, FFmpeg, network worker, upload adapter or start endpoint is added. Backend `CanStart`
is always false and no configuration switch bypasses this gate. Input checks reject file/http/IP/
local-name URLs, credentials/query/fragment and unsafe filename syntax. These checks alone are
**not claimed to solve DNS rebinding or safe media decoding**; that work must accompany an actual
retrieval adapter. Preview and confirmation cannot incur downloads, exhaust media storage, invoke
shells, overwrite files or claim indexed completion. Store size is bounded by input limits and
200 records. Existing single-owner appliance API trust boundary applies; no new identity system.

Rights attestation is recorded by explicit confirmation, not inferred from public playback or DOI.
Provider-specific terms and content rights must be established before enabling any future adapter.
User-supplied URLs/metadata stay in the Media database and are not emitted as logs in this code.

## Direct import implementation — 2026-10-18

### Components and guarantees

- `infrastructure/librarr/patches/0008-bounded-direct-audio-import.patch` extends the existing pinned
  Librarr API, organizer and SQLite owner. The Dockerfile applies it after the seven existing
  patches. Torrent source policies, routes and organization code are unchanged.
- `GET /api/v1/direct-audio-capabilities`, `PUT /api/v1/direct-audio/{id}` and status `GET` require
  the configured API key in a header even if upstream Librarr is open or session-authenticated.
  Uploads require a supported 90-second socket read deadline; transports without it fail closed.
  The body is a raw bounded audio stream, never a remote URL or client filesystem path. Headers
  bind import ID, SHA-256, format and percent-encoded display name. Body length must be known.
- `direct_audio_imports` is an additive table in Librarr's existing database, capped at 200 records.
  The immutable ID/checksum/format/name/size tuple is reserved before receiving media. Same-ID
  replays return retained state without consuming the stream; conflicting tuples fail. Interrupted
  `receiving` records are not retried. The API enforces one active request per Librarr process;
  database uniqueness and exclusive directory reservation also prevent same-ID double placement.
- `Organizer.PlaceDirectAudio` reuses the existing atomic no-overwrite directory reservation.
  A job owns `BigBrain Imports/<import-id>/`; its hidden `.pending` file is created exclusively,
  streamed with a byte limit, hashed and structurally validated, synced and made read-only.
  Exclusive hardlink publication exposes the final MP3 only after validation; existing/partial
  reservations are never reused. Directory fsync precedes the durable `indexing` outcome.
  Normal exceptions remove only that invocation's `.pending` file. A process crash can retain
  the reservation/staging; it requires manual review, never broad automatic deletion or retry.
- Configured roots and parents must be trusted service-owned directories on a local filesystem
  supporting exclusive mkdir/link and directory fsync. A symlinked root/author directory is
  refused; the job directory is held with `os.Root`. This is not protection against a malicious
  administrator or another hostile process with the same filesystem identity. No new permissions
  or mounts are created by BigBrain. The existing configured library root must already exist.
- Successful placement persists relative filename, inode, bytes and SHA-256, then uses the existing
  ABS scan integration. It remains `indexing`. A status inspection checks current file bytes/inode,
  a bounded complete ABS inventory and exact library/item/relative-path/file-inode/size plus one
  recognized audio track of positive duration. Title and DOI are never identity matches. Absent,
  ambiguous, oversized, unavailable or incompatible ABS evidence cannot produce completion.
- ABS inventory is limited to 500 items, five pages of 100, 2 MiB per response and 15 seconds total;
  redirects are refused. These are compatibility bounds, not assumptions that production fits them.
  `completed` is a persisted observation of successful reconciliation, not perpetual proof that a
  user can never later move/delete/edit a library file.

The [official ABS schemas](https://api.audiobookshelf.org/#library-file) describe `ino`,
`metadata.relPath`, size and library-item identity, but label the API docs unmaintained. The pinned
[LibraryFile implementation](https://github.com/advplyr/audiobookshelf/blob/743d9152208507a1dbf7c95c94290071338f44bd/server/objects/files/LibraryFile.js)
and [file utilities](https://github.com/advplyr/audiobookshelf/blob/743d9152208507a1dbf7c95c94290071338f44bd/server/utils/fileUtils.js)
were checked on 2026-10-18: inode is the string form of filesystem stat inode, not a content hash.
Therefore deployment must verify that Librarr and the selected ABS library see the **same underlying
files/inodes**, with the expected folder-relative layout. A copied/different mount or incompatible
schema must stay indexing; no production compatibility claim is made from mock responses.

### BigBrain retrieval, persistence and UX

- `DirectAudioTransport` owns a purpose-built HTTPS GET without proxy, cookies, redirects,
  decompression or credentials. Structural URL validation is reused. All DNS answers must be
  admitted public IPv4; mixed/private/IPv6 answers fail closed. The actual socket connects to the
  checked numeric IP once, while standard TLS validates the original hostname. No second DNS
  lookup occurs on connection. DNS itself remains the host's resolver, not a new provider.
- Limits: 64 MiB received bytes even without Content-Length, 16 KiB response headers, 10-second
  connect timeout, 60-second complete fetch and 150-second start-operation deadline. Only HTTP200
  and `audio/mpeg` are admitted. Librarr rechecks length/hash/content independently before publish.
  Linux staging is mode0600, unlinked while open and deleted on close; a process crash cannot
  strand that API staging inode. No subprocess, shell, decoder or transcoder is launched.
- `MediaUrlImportService` reuses `AudiobookAcquisitionStore.MediaUrlImportDrafts`, adding outcome
  fields to its JSON record rather than a new database or scheduler. A transaction consumes a
  confirmed, unexpired ID before fetching; active/abandoned downloading/importing states block a
  competing start. File SHA-256/size are durable before upload. A lost response is `uncertain`;
  inspection may reconcile a provider commit without fetching/uploading again. Missing evidence
  never refunds the start or authorizes replay. There is no reset/retry endpoint.
- The stable ID binds DOI, user name, source URL, selected format, timestamps, checksum, provider
  relative file/inode, ABS library and item. DOI remains non-unique. A blank display name uses
  `Ljudimport`; user names otherwise remain unchanged. Earlier blocked previews are not silently
  promoted to new execution authority. No DOI registration or content rights are invented.
- Start is separately gated by `Media:Librarr:DirectAudioImportEnabled` (default **false**), configured
  Librarr API key, ABS library ID and exact provider capability contract. A missing/old provider is
  rejected before source access. Credentials stay server-side; direct HTTP client logging is removed.
- The existing form defaults to MP3, still offers a truthfully blocked M4A choice, previews without
  network, records explicit rights/details confirmation, then offers a separate Start button.
  UI shows retained result/uncertainty and explicit status inspection; it does not poll hidden views
  or start unattended work. The request-bound operation is cancellable on navigation; it is **not**
  a detached background worker. Reload shows retained state. A completed item links to the existing
  configured public ABS URL, when available; no old embedded player is opened. Experimental UX Lab
  remains inert and unapproved. Existing Media navigation/search are preserved.

### Supported subset and safety limits

Only direct same-format **MPEG-1 Layer III MP3 without ID3/APE tags**, with at least two complete
frames and consistent sample rate/channel mode, is admitted. Truncated frames, reserved bitrate/
sample-rate/emphasis and different content are refused. M4A, tagged MP3, other MPEG versions,
conversion, YouTube, URL parameters, redirects and IPv6 destinations remain unsupported. This
narrow framing validator is bounded and does not execute codec payloads. It is **not** a full audio
decoder, malware detector or proof that a downstream decoder has no vulnerabilities. Existing ABS
scanner isolation/patch level must be acceptable before activation; malformed-but-framed payload
risk must be reviewed. No new decoder sandbox or relaxed provider policy is silently introduced.

The full original M4A/MP3 Definition of Done is not claimed. Remaining code work is verified
admission for additional formats/tag structures if required; the current checkpoint deliberately
publishes the functional MP3 subset for security/architecture review. No automatic retry, cleanup
of uncertain library reservations, general downloader, new service or production activation.

| APE on MP3 | Trailing APEv2 UTF-8 text items before optional ID3v1, footer and optional exact matching header | ≤4MiB envelope, ≤1024 unique case-insensitive keys, 2–255 ASCII key bytes, validated lengths/flags/reserved bytes, ≤1024 value separators/item. APEv1, leading APE, binary/locator items and conflicting headers rejected. |
| M4A | Progressive unencrypted single-track AAC-LC, mono/stereo, standard two-byte AudioSpecificConfig, self-contained data reference, `mp4a` entry | One moov and one mdat; ≤4MiB moov, ≤512 boxes, ≤1,000,000 samples/table entries, ≤1MiB/sample. Exact count/size/offset/duration consistency; all samples contiguous, nonoverlapping and exhaust mdat. Fragmented/multitrack/video, ALAC/HE-AAC, DRM, external data references, unsupported optional boxes/config extensions rejected. |

M4A supports moov before/after mdat, stco/co64 offsets, extended-size mdat, common bounded iTunes
metadata envelopes and bounded v0 edit-list envelopes. Nested box structure has a fixed known
hierarchy; unknown containers are rejected, not recursively traversed. Metadata values stay opaque.
Size-zero/undersized/overflowing boxes, excessive counts, mismatched sample bytes/timing, duplicate
structural boxes, external references and protected audio entries are refused. No ftyp-only admission.

These are **structural validators, not full audio decoders or malware scanners**. Synthetic coded
samples test structural admission; tests do not assert perceptual playback or decoding of all payloads.
Valid framed compressed bytes can still stress a downstream decoder. ABS scanner isolation and
patch level remain a separate operational prerequisite. Not every otherwise valid MP3/M4A variant
is supported; unsupported files fail safely rather than being converted or silently treated as MP3.
